Close the remaining performance gaps between the v6 branch and v5.0.31 in @colyseus/schema, one sub-agent per gap, with every change proven by the bench harness's A/B protocol.

## Read first (in this order)

1. `bench/v6-open-gaps.md` — the five gaps, fresh numbers, profiled causes, source pointers and suggested experiments. This is the task list.
2. `bench/realworld-results.md` — what the previous round changed and measured (x1–x10), what was rejected and why (do not retry x4 typed-dispatch as-is; the dictionary-mode refId theory is false; the setter's cost is bookkeeping, not loads).
3. `bench/README.md` — the A/B protocol (N ≥ 20, ABBA, accept at p < 0.05 and |Δ| ≥ 2 % with no other row regressing > 2 %), the scenario contract, and the "V8-level profiling" / "Real-world scenarios" sections.
4. `bench/array-impl-comparison.md` — only for the ArraySchema gap.

Baselines on this machine (gitignored, rebuild if missing): `bench/.builds/v5-release` (master 5.0.31), `bench/.builds/x10-noshrink` (= the working tree at the end of the last round; freeze the current tree first with `npm run bench:snapshot base` and use that as A). If `v5-release` is missing: `git worktree add %TEMP%\schema-v5 master`, junction `node_modules`, `npm run build` there, copy `build/index.mjs` into `bench/.builds/v5-release/`.

## Hard rules

- Every source change: `npm test` green (1055 tests; run from PowerShell), then `npm run bench:snapshot <label>`, then `node bench/run.mjs --compare bench/.builds/<A> bench/.builds/<label> --samples 20 --filter "<targets>"`, then the relevant group of the existing matrix for regressions. Record hypothesis → numbers → verdict in `bench/realworld-results.md` under a new "Round 2" section, and update `bench/v6-open-gaps.md` (remove or shrink the gap; keep the numbers).
- Wire format is frozen this round unless a projection from `bench/lib/wire-whatif.mjs` shows ≥ 5 % on a real-world shape; any wire change needs `SPEC.md`, `CHANGELOG.md`, tests and a note that other-language decoders must follow.
- Benchmarks are CPU-sensitive: run compares one at a time. Long chains go in a detached Git Bash script (`Start-Process "C:\Program Files\Git\bin\bash.exe" -ArgumentList "/c/.../script.sh"`), log to `%TEMP%`, watch the log; never edit `bench/lib/*.mjs` or a scenario while a sweep runs.
- Never reset a scratch array with `length = 0` on a hot path (V8 drops the backing store); never call `view.add(state)` on a populated state in a scenario; `t.quantized()` builders only through `schema({})`, the decorator path takes `{ quantized: opts }`.
- Profile before changing: `node bench/profile.mjs --cpu <unit> --interval 100 --build bench/.builds/<label>`, `node bench/profile-v8.mjs --deopt|--ic|--inlining <unit>`, `--shapes` for hidden-class questions.
- No commits unless asked. Sub-agents work in their own git worktree (`isolation: "worktree"`) and hand back a diff plus their measured table; the main session applies the diffs one at a time onto the branch, re-runs the full suite and the targeted compare after each, and resolves conflicts (all five touch the encoder; expect overlap in `src/encoder/Encoder.ts` and `src/encoder/EncodeOperation.ts`).

## Sub-agents (launch the first four in parallel; each gets the rules above verbatim plus its section)

**Agent A — tiny-tick fixed cost** (`bench/v6-open-gaps.md` §1). Targets: `realworld/small-patch/root-field` (+49 %), `one-entity` (+20 %), `realworld/turn-based/enc` (+12 %) against v5; must not move `realworld/large-patch/*`, `encoder/*` or `stateview/views/*` by more than noise. Order of experiments: (1) `releaseFrames` in `src/encoder/EncodeOperation.ts` — explicit `valsLen`/`strsLen` counters instead of `length = 0`, and skip the loop when only frame 0 was touched and holds no scratch (track the max depth used per tick); (2) slim `_beginPass` in `src/encoder/Encoder.ts` (inline `passFrame`, hoist the `pendingFilterRefresh` check, fewer stores); (3) a Schema-only `enterFrame` fast path (skip `childWriterOf`/`keyWriterOf` when `desc.kind === KIND_SCHEMA`); (4) check `discardChanges` → `discardQueue` → `endEncode` for per-tree work that a one-tree tick can skip. Profile `small-patch/root-field` at `--interval 100` before and after each step; the A/A floor is ±2 % at N = 8 there, so use N = 20.

**Agent B — `stateview/tags`** (§2). Target: `stateview/tags/default` (+20 % vs v5); guard `stateview/views/*`, `stateview/view-churn`, `e2e/room-tick`, `realworld/mmo-shards/*`. Start with `--cpu --interval 50` on the current build to split `_emitViewTrees` self time (list build / `tagKey` / emission / `_cacheChunk`). Then: resolve a view's custom-tag bits against a tree once per (view, tree) and reuse it for both `tagKey` and the per-field `Schema[$filter]` → `hasTagOnTree` calls (`src/encoder/Encoder.ts` `tagKey`, `src/Schema.ts` `[$filter]`, `src/encoder/StateView.ts` `hasTagOnTree`); measure the chunk cache off (`useCache = false`) for this shape to see whether memcpy pays at 10 views; consider caching per tree per tick the tag-key → cached-chunk mapping instead of recomputing per view.

**Agent C — ArraySchema iteration and `shift`** (§3). Targets: `mutations/array-iterate/indexOf-last` (+165 %), `shift-push` (+116 %), `forEach` (+39 %), `filter` (+20 %), `mutations/array-refs/push-shift-2000` (+123 %), `decoder/array-read/indexOf-last` (+137 %), `filter` (+22 %), `forEach` (+20 %); guards: `decoder/array-read/index`, `length+at`, `for-of` (v6's 37–98 % wins must stay), `encoder/array-churn`, `stateview/array-reindex/*`. Do NOT change the storage model (that decision is the user's; `bench/array-impl-comparison.md` has the trade-off) — tighten the overrides in `src/types/custom/arrayOps.ts` and `src/types/custom/ArraySchema.ts`: `indexOf`/`lastIndexOf`/`includes` with the comparison hoisted per element kind, `forEach`/`filter`/`map` without per-element `this` rebinding or closure allocation, and a `shift`/`splice(0, n)` path that slides with a typed loop and no per-element write-barrier surprises (verify with `--deopt` and `--cpu`). If a builtin can be called natively without the generic-path penalty in some case (e.g. on the decoder-side instance for read-only ops), prove it with `mutations/array-iterate/*` and `decoder/array-read/*` rather than assuming. Report the storage-model question back to the user with the final numbers instead of deciding it.

**Agent D — strings and memory** (§4 + §5). Targets: `encoder/string-heavy` (+4 %), `encoder/memory-footprint` (+6 %, `measure: "heap"`, use N = 20); guards `realworld/lobby-chat/*`, `realworld/big-state/*`, `decoder/*`. Strings: single-pass `writeString` for short strings (write UTF-8 behind a reserved length byte and back-patch, shifting only when the length reaches 128, like `endChunk` in `src/encoding/varint.ts`); `TextEncoder.encodeInto` above ~64 chars and `TextDecoder` in `utf8Read` (`src/encoding/decode.ts`) above ~24 chars — measure the crossover, keep the char loops below it. Memory: move `decodeInfo` off `ChangeTree` (`src/encoder/ChangeTree.ts`) to `UntrackedChangeTree` plus a `WeakMap` fallback for a Decoder decoding into a tracked instance (`src/decoder/DecodeOperation.ts` `refInfoOf`); confirm with `--shapes` that `ChangeTree` instances keep one map and check whether the in-object slot count is what grew.

**Agent E — after A–D are merged: the full re-baseline** (sequential, detached script, ~3 h). v5-release vs the merged build on `realworld/*` at N = 20, then the merged build vs `x10-noshrink` on every existing group at N = 12, then `npm run bench:gate`. Update `bench/realworld-results.md` (a "Round 2" final table), rewrite `bench/v6-open-gaps.md` to what remains, and add budgets (`gate: true`, `budget` ≈ 2× the new median) to `realworld/small-patch/root-field`, `realworld/large-patch/enc-5k` and `realworld/entities-aoi/n2000-c50`.

Deliverable of the session: the merged diffs on the v6 working tree (uncommitted), all tests green, the updated two documents, and a final message listing per gap the before/after numbers and what, if anything, is still slower than v5.
